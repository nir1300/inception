containers
like a vm, has an OS, but dont simulate entire computer, create an environment specifically for 1 job to work
run smallest possible version of software/OS
only expose the ports needed to do their job on the network -> hacker cant talk to them like a regular computer
when deploying to production, no need to set up separate servers -> just save containers into image files and run those (different OS/env doesnt matter -> docker handles translation between container and host)


docker
a way to build and run those containers, can save them into templates


dockerfile
= instruction file that tells docker to download an image, run commands on it (e.g. install additional software/packages)


docker compose
= uses docker commands to set up and start containers, write YAML file and docker compose translates that into necessary docker engine commands


difference bw docker image used with and without docker compose


docker vs vm's
docker is more lightweight -> you dont loose much performance
